01 · Complejidad algorítmica

¿Qué tan rápido es "rápido"?

Un programa que tarda un segundo con 100 elementos puede tardar horas con 10 millones — y esa diferencia casi nunca se nota probando con datos pequeños.

Analogía · el diccionario de papel

Buscar "casa" página por página desde la A tarda más mientras más grueso sea el libro. Pero si el diccionario está ordenado, puedes abrirlo por la mitad y descartar media mitad del libro en cada paso — esa diferencia es la de esta semana.

La complejidad mide cómo crece el trabajo de un algoritmo cuando crece el tamaño de la entrada (n) — no mide segundos de reloj, mide la forma en que ese trabajo escala.

02 · Búsqueda

Búsqueda lineal: revisar todo, en orden

La estrategia obvia: recorrer la lista elemento por elemento. No necesita que esté ordenada.

lineal.pypython
def busqueda_lineal(lista, objetivo):
    for indice, valor in enumerate(lista):
        if valor == objetivo:
            return indice   # lo encontramos aquí
    return -1                # no está en la lista
Peor caso

Si el elemento está al final, o no está, se revisan los n elementos. Complejidad O(n): el doble de datos, el doble de trabajo.

02 · Búsqueda

Búsqueda binaria: descartar la mitad

Si la lista está ordenada, comparar con el medio permite descartar la mitad de los datos en cada paso.

binaria.pypython
def busqueda_binaria(lista_ordenada, objetivo):
    izquierda, derecha = 0, len(lista_ordenada) - 1
    while izquierda <= derecha:
        medio = (izquierda + derecha) // 2
        if lista_ordenada[medio] == objetivo:
            return medio
        elif lista_ordenada[medio] < objetivo:
            izquierda = medio + 1   # descarta la mitad izq.
        else:
            derecha = medio - 1     # descarta la mitad der.
    return -1
log₂(n) vueltas

Cada vuelta descarta la mitad de lo que quedaba. Con 1.000 elementos alcanzan ~10 comparaciones; con 1.000.000, ~20. Complejidad O(log n).

03 · Notación Big O

Comparar algoritmos sin ejecutarlos

Describe cómo crece el trabajo en el peor caso, ignorando constantes y detalles de la máquina.

NotaciónNombreEjemplo de esta semana
O(1)Constantediccionario["clave"]
O(log n)Logarítmicabusqueda_binaria()
O(n)Linealbusqueda_lineal()
O(n log n)Cuasi-linealsorted() / .sort()
O(n²)Cuadráticabubble sort

Intuición

Analogía: contratar gente para mudar cajas

O(1)

Una mirada

"¿Está la caja azul en la puerta?" — sin importar cuántas cajas haya en total.

O(n)

Caja por caja

Revisar una por una hasta encontrar la azul.

O(n²)

Comparar contra todas

Por cada caja, comparar su peso contra el de todas las demás — el doble de cajas cuadruplica el trabajo.

04 · Ordenamiento

Bubble sort: comparar e intercambiar

Compara elementos adyacentes y los intercambia si están en el orden incorrecto — repite hasta que no queden intercambios.

bubble_sort.pypython
def bubble_sort(lista):
    n = len(lista)
    for pasada in range(n - 1):
        for i in range(n - 1 - pasada):
            if lista[i] > lista[i + 1]:
                lista[i], lista[i + 1] = lista[i + 1], lista[i]
    return lista

print(bubble_sort([5, 2, 9, 1, 5, 6]))
Resultado[1, 2, 5, 5, 6, 9]

Analizando bubble sort

Un ciclo dentro de otro ciclo

El ciclo externo recorre la lista n veces, y por cada vuelta el ciclo interno vuelve a recorrer casi toda la lista comparando pares — el patrón "por cada elemento, comparar contra los demás".

Punto de confusión clásico

Que bubble sort sea O(n²) no es un error de código: con 100 elementos hace ~10.000 comparaciones; con 100.000, ~10.000.000.000. Por eso en producción siempre se usa sorted()/.sort(), nunca una implementación manual.

Mirando adelante · IA y Machine Learning

Por qué esto importa para IA/ML

Búsqueda vectorial en RAG

Comparar contra cada vector uno por uno es O(n) y se vuelve lento con millones de vectores — por eso existen índices especializados que se acercan a O(log n), igual que la búsqueda binaria.

Entrenar con 10.000 filas vs. 10.000.000 no escala solo por el tamaño: la complejidad del algoritmo de entrenamiento decide si ese crecimiento es manejable o impráctico. Y NumPy/Pandas (Semana 9) son rápidos por la misma razón por la que sorted() le gana a un bucle manual: algoritmos eficientes, implementados en C.

05 · Ejemplo práctico

Del pseudocódigo al código real

comparacion.pypython
# Lista ordenada de 1000 números: 0, 2, 4, ..., 1998
numeros = [n * 2 for n in range(1000)]
objetivo = 1996   # casi al final de la lista

print(busqueda_lineal_contada(numeros, objetivo))
print(busqueda_binaria_contada(numeros, objetivo))
ResultadoLineal: 999 · Binaria: 9

Con 1.000 elementos, la lineal recorrió casi toda la lista (su peor caso); la binaria lo encontró en 9 pasos — confirma en la práctica la diferencia entre O(n) y O(log n).

06 · Segundo ejemplo

Bubble sort vs. sorted(): mismo resultado, distinta idea

comparacion_orden.pypython
desordenado = [64, 25, 12, 22, 11]

# bubble sort: escrito a mano, O(n²), modifica la copia
copia = desordenado.copy()
resultado_manual = bubble_sort(copia)

# sorted(): función nativa, O(n log n), lista nueva
resultado_nativo = sorted(desordenado)

print(resultado_manual == resultado_nativo)   # True
.copy() evita modificar el original

bubble_sort() modifica la lista que recibe; se le pasa una copia para poder comparar contra sorted(desordenado) sin haberlo alterado antes.

Nota de vigencia técnica · 2026

Big O no cambia; la implementación sí

Big O es matemática de ciencias de la computación y no cambia con las versiones del lenguaje. Lo que sí conviene tener actualizado es qué algoritmo implementa Python por debajo.

sorted() / .sort() usan Timsort: híbrido merge + insertion sort, O(n log n)
Timsort es estable: conserva el orden relativo de elementos "iguales"

Autoevaluación

01¿Qué mide Big O: segundos de reloj o cómo crece el trabajo?

RespuestaCómo crece el trabajo a medida que crece n; no mide segundos de reloj.

02¿Por qué la búsqueda binaria necesita la lista ordenada y la lineal no?

RespuestaLa binaria decide qué mitad descartar comparando con el medio, válido solo si los datos están ordenados; la lineal revisa uno por uno sin depender del orden.

03Con 1.000.000 de elementos, ¿cuántas comparaciones necesita la búsqueda binaria en el peor caso?

RespuestaAproximadamente 20 (log₂(1.000.000) ≈ 20), frente al 1.000.000 de la lineal.

04Ordena de más a menos eficiente: O(n²), O(1), O(n log n), O(log n), O(n).

RespuestaO(1) < O(log n) < O(n) < O(n log n) < O(n²).

05¿Por qué bubble sort es O(n²)?

RespuestaPor cada uno de los n elementos, vuelve a recorrer casi toda la lista comparando pares adyacentes.

RespuestaFalso; sorted()/.sort() usan Timsort (O(n log n)), en C, más eficiente y confiable.

08¿Qué error se comete al usar / en vez de // para el punto medio?

Respuesta/ produce un float (ej. 2.5), y una lista no puede indexarse con un float.
