01 · Por qué organizar el código

De funciones sueltas a objetos

Los datos y las funciones que los manipulan han vivido separados hasta ahora. A medida que un programa crece, esa separación empieza a pesar.

Analogía · un auto

Un auto tiene datos propios (color, velocidad, combustible) y comportamientos que actúan sobre ellos (acelerar, frenar, cargar). Nadie los piensa por separado — son del mismo auto.

La POO agrupa datos (atributos) y las funciones que operan sobre ellos (métodos) en una sola unidad: el objeto.

02 · Clases y objetos

class, __init__ y self

Una clase es el molde; un objeto es el resultado concreto de usarlo.

estudiante.pypython
class Estudiante:
    def __init__(self, nombre, notas):
        self.nombre = nombre   # atributo de instancia
        self.notas = notas     # atributo de instancia

    def promedio(self):
        return sum(self.notas) / len(self.notas)

ana = Estudiante("Ana", [6.5, 7.0, 5.8])
print(ana.promedio())
Resultado6.433333333333334
self

Representa "el objeto sobre el que se trabaja ahora". Python lo pasa automáticamente al llamar ana.promedio() — nunca se pasa a mano.

03 · Atributos

Atributos de instancia vs. de clase

Uno pertenece a un objeto en particular; el otro es compartido por todas las instancias.

estudiante.pypython
class Estudiante:
    total_estudiantes = 0   # atributo de clase: compartido

    def __init__(self, nombre, notas):
        self.nombre = nombre   # atributo de instancia: propio
        Estudiante.total_estudiantes += 1
Punto de confusión clásico

Usar una lista mutable como atributo de clase hace que todos los objetos compartan (y modifiquen) la misma lista. Los datos propios de cada objeto van en __init__, con self.

04 · Control de versiones

Git: puntos de guardado del código

Si un archivo se rompe o se borra por accidente, sin historial la única salida es tener una copia guardada a mano.

Analogía · puntos de guardado de un videojuego

Si algo sale mal, se vuelve al último punto guardado en vez de empezar de nuevo. Un commit es exactamente eso: una fotografía del proyecto completo, con un mensaje que describe qué cambió.

A diferencia de "Ctrl+Z", el historial de Git no se pierde al cerrar el editor — y funciona igual de bien en un proyecto de una persona que en uno de cien.

04 · Control de versiones

Comandos esenciales

terminalbash
# convierte la carpeta en un repositorio (una sola vez)
git init

# marca cambios para el próximo commit
git add cuenta.py

# guarda el punto de guardado, con mensaje
git commit -m "Agrega clase Estudiante"

# muestra el historial de commits
git log
.gitignore

Le dice a Git qué archivos generados automáticamente (como __pycache__/) nunca debe rastrear, porque se regeneran solos.

05 · Testing automatizado

Probar el código con código

Probar a mano con print() funciona una vez — pero hay que repetirlo cada vez que el código cambia, y es fácil olvidar un caso.

assert.pypython
def promedio(notas):
    return sum(notas) / len(notas)

assert promedio([6.0, 8.0]) == 7.0   # pasa en silencio

Si la condición de assert es verdadera, no pasa nada; si es falsa, Python lanza un error de inmediato.

05 · Testing automatizado

pytest: el estándar de la industria

test_promedio.pypython
from calculadora import promedio

def test_promedio_de_dos_numeros():
    assert promedio([6.0, 8.0]) == 7.0

def test_promedio_con_un_solo_numero():
    assert promedio([5.0]) == 5.0
Descubrimiento automático

Cualquier función test_* dentro de un archivo test_*.py es reconocida por el comando pytest sin configuración extra.

Mirando adelante · IA y Machine Learning

Por qué esto importa para IA/ML

scikit-learn usa el mismo patrón de POO

Cada modelo es un objeto con métodos .fit() y .predict() (Módulo 10) — entender clases y self hoy es entender esas herramientas más adelante.

Un modelo entrenado sin Git es casi imposible de reproducir. Y un pipeline de datos sin pruebas puede fallar en silencio: una función de limpieza mal escrita puede arruinar un entrenamiento completo sin lanzar ningún error visible.

06 · Ejemplo práctico

CuentaBancaria: modelar, versionar, probar

Depósitos y retiros, evitando que un retiro deje el saldo negativo.

cuentapseudocódigo
CLASE CuentaBancaria
    METODO retirar(monto)
        SI monto > self.saldo ENTONCES
            LANZAR ERROR "fondos insuficientes"
        self.saldo = self.saldo - monto

06 · Ejemplo práctico

Del pseudocódigo al código real

cuenta.pypython
class CuentaBancaria:
    banco = "Banco Gutyy"   # atributo de clase

    def __init__(self, titular, saldo_inicial=0):
        self.titular = titular
        self.saldo = saldo_inicial

    def retirar(self, monto):
        if monto > self.saldo:
            raise ValueError("fondos insuficientes")
        self.saldo -= monto

raise ValueError(...) interrumpe la ejecución con un mensaje, en vez de dejar que el saldo quede negativo.

06 · Ejemplo práctico

Pruebas con pytest

test_cuenta.pypython
import pytest
from cuenta import CuentaBancaria

def test_retiro_sin_fondos_lanza_error():
    cuenta = CuentaBancaria("Ana", saldo_inicial=100)
    with pytest.raises(ValueError):
        cuenta.retirar(500)   # debe fallar
pytest.raises(ValueError)

Espera que el código de adentro lance ese error. Si lo lanza, la prueba pasa; si termina sin lanzarlo, la prueba falla.

06 · Integrando todo

El flujo de trabajo completo

terminalbash
git init
git add cuenta.py test_cuenta.py
git commit -m "Agrega CuentaBancaria con sus pruebas"
pytest
Resultado3 passed

Un cambio de comportamiento sin su prueba correspondiente, o una prueba sin el código que la haga pasar, es un commit incompleto.

Nota de vigencia técnica · 2026

Qué se mantiene y qué evoluciona

pytest es hoy el estándar de facto de testing en Python, sobre unittest (stdlib)
Los comandos base de Git no han cambiado desde su creación en 2005
@dataclass (Python 3.7+) genera __init__ automáticamente para clases de solo-datos

Cierre · Parte 1 de 2

Autoevaluación

01¿Qué representa self dentro de un método?

RespuestaEl objeto sobre el que se llama el método; Python lo pasa automáticamente, nunca se pasa a mano.

02¿Diferencia entre atributo de instancia y de clase?

RespuestaEl de instancia pertenece a un objeto (definido con self. en __init__); el de clase es compartido por todas las instancias.

03¿Por qué usar una lista como atributo de clase suele ser un error?

RespuestaTodos los objetos terminarían compartiendo y modificando la misma lista, en vez de tener cada uno la suya.

04¿Diferencia entre git add y git commit?

Respuestaadd marca cambios para el próximo punto de guardado; commit los guarda de forma permanente, con mensaje.

05¿Para qué sirve un archivo .gitignore?

RespuestaLe dice a Git qué archivos generados automáticamente (como __pycache__/) nunca debe rastrear.

Cierre · Parte 2 de 2

Autoevaluación (continuación)

06¿Qué hace assert condicion cuando condicion es falsa?

RespuestaLanza un error inmediatamente, interrumpiendo la ejecución; si es verdadera, no hace nada visible.

07¿Cómo identifica pytest qué funciones son pruebas?

RespuestaBusca archivos y funciones cuyo nombre empiece con test_.

08V/F: "assert True siempre pasa, así que confirma que el código funciona."

RespuestaFalso; no verifica ningún valor real y solo da una falsa sensación de seguridad.

09Sin jerga técnica: ¿por qué un equipo de ML necesita Git además de pruebas?

RespuestaSin Git es casi imposible saber qué versión de código produjo un modelo entrenado; sin pruebas, un cambio en la preparación de datos puede arruinar un entrenamiento sin que nadie lo note.
