01 · De la analogía a la sintaxis

La caja etiquetada, ahora en código real

En la Semana 1, la variable era un casillero etiquetado. Hoy esa idea se convierte en una sola línea de sintaxis ejecutable.

Crear una variablepython
edad = 30

A la izquierda, la etiqueta del casillero (edad). A la derecha, lo que se guarda dentro (30). El signo = es asignación, no "igual a" — la misma distinción con == que ya vimos con el paraguas en la Semana 1.

Reglas (obligatorias)

Solo letras, números y _; no empieza con número. Distingue mayúsculas de minúsculas. No usa palabras reservadas (if, for...).

Convención (buena práctica)

snake_case y nombres descriptivos: precio_total en vez de pt.

02 · Tipos de datos

Los cuatro tipos de datos primitivos

No todos los casilleros son iguales: un frasco no guarda lo mismo que una botella. El tipo determina qué operaciones tienen sentido.

TipoPythonEjemploAnalogía
Número enteroint30, -4, 0Contar personas: no hay "2.5 personas".
Número decimalfloat1.75, -0.5Medir estatura o peso: sí admite fracciones.
Textostr"Ana", "30"Un letrero: aunque diga "30", son letras.
Verdadero/falsoboolTrue, FalseUn interruptor: solo dos posiciones.

Explorando tipos

type(): preguntarle a Python qué hay en el casillero

tipos.pypython
edad = 30
estatura = 1.75
nombre = "Ana"
es_estudiante = True

print(type(edad))          # <class 'int'>
print(type(estatura))      # <class 'float'>
print(type(nombre))         # <class 'str'>
print(type(es_estudiante))  # <class 'bool'>
El truco que confunde a todo principiante

"30" (con comillas) y 30 (sin comillas) se ven casi iguales, pero son tipos distintos. Solo con el segundo puedes hacer 30 + 1. Es la causa número uno de errores al leer datos del teclado.

03 · Operadores

Lo que se puede hacer con cada tipo

Aritméticos

+ - * / // % **

7 / 2 → 3.5 · 7 // 2 → 3 · 7 % 2 → 1 · 2 ** 3 → 8

Comparación

== != > < >= <=

Dan siempre un bool como resultado. Ya los usamos en la Semana 1, dentro de un SI.

Ejemplo

Python distingue mayúsculas también en texto

"Ana" == "ana" → False

operadores.pypython
print(7 / 2)    # 3.5   → división siempre da float
print(7 // 2)   # 3     → división entera (descarta el resto)
print(7 % 2)    # 1     → módulo: el resto de la división
print(2 ** 3)   # 8     → potencia

Conectando con la Semana 1

El bool que vive dentro de cada decisión

edad >= 18 no es solo una condición abstracta: Python la evalúa y produce un valor concreto de tipo bool, que el if usa para decidir el camino.

bool_ejemplos.pypython
print(18 >= 18)         # True
print("Ana" == "ana")  # False

"El bloque de decisión de la Semana 1 no era metáfora: por dentro siempre fue un bool."

04 · Entrada y salida

Recibir datos de quien usa el programa

Hasta ahora los datos venían "cableados" en el código. Un programa real necesita recibirlos de una persona.

saludo.pypython
nombre = input("¿Cómo te llamas? ")
print(f"Hola, {nombre}")
Analogía · el mesero

input() es como un mesero que, sin importar lo que pidas, siempre lo anota en un papel: el papel (texto) es el medio, no el contenido real. Lo que la persona escriba llega siempre como str, aunque teclee solo números.

edad_texto.pypython
edad = input("¿Cuántos años tienes? ")
print(type(edad))  # <class 'str'>  — ¡aunque hayas tecleado "18"!

05 · El arreglo

Conversión explícita de tipos

edad + 1 falla con este edad: Python no sabe sumar texto con número. La solución es convertir.

edad_convertida.pypython
edad = int(input("¿Cuántos años tienes? "))  # convierte de inmediato
print(edad + 1)   # ahora sí funciona
Tres conversiones comunes

int("30") → 30 · float("1.75") → 1.75 · str(30) → "30"

Si el texto no es realmente ese tipo

int("hola") truena con un ValueError claro.

06 · Salida legible

f-strings, formalizadas

Anteponer f a un string permite insertar variables directamente entre llaves, sin concatenar a mano.

fstrings.pypython
nombre = "Ana"
edad = 30
print(f"{nombre} tiene {edad} años")                        # f-string: legible
print(nombre + " tiene " + str(edad) + " años")  # equivalente, más frágil

Mirando adelante · IA y Machine Learning

Por qué esto importa para IA/ML

Cada modelo procesa datos que primero pasaron por exactamente esta misma disciplina de tipos.

Todo termina en números

Una imagen no es "una foto" para el modelo: es una matriz de números (float). Una reseña de producto tampoco es "texto libre" para siempre: eventualmente se convierte en números también.

El primer error de casi cualquier persona empezando en ciencia de datos es operar sobre una columna que, sin que lo note, Python sigue tratando como texto — el mismo TypeError de edad + 1, a mayor escala.

"Con pandas o NumPy, la primera pregunta de diagnóstico siempre va a ser la misma que hoy: ¿de qué tipo es realmente este dato?"

07 · Ejemplo práctico

Del pseudocódigo al código real

imc.pypython
# ENTRADA: input() siempre da texto, convertimos de inmediato con float()
peso = float(input("Ingresa tu peso en kilogramos: "))
estatura = float(input("Ingresa tu estatura en metros: "))

# PROCESAMIENTO
imc = peso / (estatura ** 2)

# DECISIÓN: "SI NO SI" se traduce a elif
if imc < 18.5:
    categoria = "Bajo peso"
elif imc < 25:
    categoria = "Peso normal"
else:
    categoria = "Sobrepeso"

# SALIDA: :.1f redondea a 1 decimal
print(f"Tu IMC es {imc:.1f} ({categoria})")
ResultadoTu IMC es 23.0 (Peso normal)
Punto de confusión clásico

elif no es lo mismo que varios if sueltos. En cuanto una condición se cumple, Python ejecuta esa rama y se salta el resto de la cadena — con if sueltos, evaluaría todos, y los resultados pueden pisarse entre sí.

08 · Segundo ejemplo

Promedio de tres calificaciones

Los mismos bloques de la Semana 1 — secuencia y decisión — ahora con tipos y entrada real.

promedio.pypython
nota1 = float(input("Nota 1: "))
nota2 = float(input("Nota 2: "))
nota3 = float(input("Nota 3: "))

promedio = (nota1 + nota2 + nota3) / 3   # SECUENCIA

if promedio >= 6.0:                       # DECISIÓN
    resultado = "Aprobado"
else:
    resultado = "Reprobado"

print(f"Promedio: {promedio:.2f} — {resultado}")

Nota de vigencia técnica · 2026

Sintaxis estable, sin partes desactualizadas

Variables, tipos primitivos, input()/print() y f-strings son sintaxis estable desde hace años y siguen siendo la forma estándar de escribir Python en 2026.

Se mantiene Python 3.12+ · se prioriza f-strings sobre .format() o concatenación con +

Las f-strings son más legibles y son la convención dominante en el código Python actual.

Autoevaluación

01¿Por qué edad = input(...) no permite hacer edad + 1 directamente?

Respuestainput() siempre devuelve str, sin importar lo tecleado; Python no suma texto con número sin conversión explícita.

02¿Cuál es la diferencia entre "30" y 30?

Respuesta"30" es str; 30 es int. Se ven parecidos al imprimirse pero admiten operaciones distintas.

03¿Qué hace exactamente = en total = precio * cantidad?

RespuestaAsigna: calcula la derecha y la guarda en el nombre de la izquierda. No es comparación (para eso es ==).

04Tipo resultante de: a) 7 / 2  b) 7 // 2  c) "7" + "2"  d) 7 == 2

Respuestaa) float (3.5), b) int (3), c) str ("72", concatenación), d) bool (False).

05¿Por qué se usa elif en vez de varios if sueltos en la calculadora de IMC?

RespuestaCon elif, al cumplirse una condición se ejecuta esa rama y se salta el resto; con if sueltos, Python evaluaría todos, con resultados que podrían pisarse.
